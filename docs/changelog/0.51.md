`600fbd0db3ad761a92cf8418daac3517539b1da2` across native development dependencies
and the release-editor/Testkit CLIs. The release renderer and metadata observer
retain their contracts; native memory accounting and Testkit startup share their
existing state/coordination owners. Existing admitted CLI installations can be
reused through explicit `make install-release-tools install-runtime-server`.

Both dependency catalogs select Platform 0.6.16 at
`0b84c2eb68239aaee4a95de35f82e702e138dcf0`. The independent lock changes only its
Platform version/checksum, retaining PocketIC 16.1.0 and all other selections.
The incoming root lock also selects Metrics 0.16.2 at
`0d60020987fe706e8182b6d4ab9c87a406876f16`; its Rust source matches 0.16.1.
Stable-structures 0.7.2, Platform's stable-memory/PocketIC facades and the selected
feature boundaries remain unchanged. No retained-data conversion, caller type
migration or compiler change is required.

Coordinated release adapters read one ordered package roster across native Rust,
archive qualification and interrupted-metadata bootstrap. Release-file checks
reuse expected source projections within an admission phase while reobserving
working files after effects. Existing receipt JSON fields, publication order,
retained archives, rollback and stale-source refusals remain unchanged.

Preparation names its fixed command steps; receipt checks distinguish stage and
archive location explicitly. Native command execution and output capture have
separate results. Release fixtures use admitted typed faults and separate command
families, retaining the same independent failure and recovery assertions. Invalid
rosters stop before cache preparation or helper dispatch.

One consumer script owns both formatter modes and the two-workspace operation
list. Installed qualification iterates Memory and Storage artifacts through the
same original/O3/Os/Oz flow; Testkit retains server lifecycle and Make retains
prerequisite/build ordering. Neither path installs tools or changes dependency
selection.

Sealing, resolution and historical admission share the external-declaration
ceiling without changing its value. Fixture doctor status is projected from its
actual read result, removing independently representable status/record state;
public reports and observations before policy callbacks remain unchanged.

The follow-up cleanup derives archive workspace membership, registry patches,
source hashes and local-package admission from one extracted-package map. Exact
external dependency selections, unique package identities and before/after
archive/source integrity remain required; negative fixtures also substitute
manifest paths and add unexpected local packages before compilation.

Release inspection carries a named commit/intent result, and release surfaces
carry immutable original/candidate bytes together. Current files, index contents,
refs and archives are still observed independently around effects. Fixture callers
construct typed faults directly; fixture revision selection has one projection.
The existing Wasm-size adapter now builds and checks from the same probe roster.

`make test-offline-tool-reuse` runs the consumer probe used by CI, admitting the
prepared tools before its disposable-consumer reuse checks. The independent
runtime runner decodes its exact snapshot into named fields and still rejects
truncated/trailing bytes. Ledger key lookup has one private implementation;
resolution, admission and claim policy remain at their existing callers.
Histogram continuity retains its explicit bounded loop: an iterator rewrite
would add projection machinery without matched Wasm-cost evidence.

## [0.51.0] - 2026-10-24

### IC Metrics 0.16

The stable adapter now consumes published `ic-metrics` 0.16.0 at
`c0f033a8f41c280fd0fc77b2ec934d2f2b8176ed`. Its arithmetic Rust source is
unchanged from 0.15.8; the upstream minor release retires adapter publication
from IC Metrics after the transfer to Persistence. Arithmetic remains independent
and has no production dependencies.

**Breaking:** the adapter exposes Metrics arithmetic and state-error types in
its public API. Cargo treats the 0.15 and 0.16 packages as different type
identities. Hosts using those APIs must update their direct requirement to
`ic-metrics = "0.16"` alongside this Persistence release. No source shim or
parallel arithmetic version is introduced. Adapter Rust source, V1 records,
continuity checks, allocation leases and the map format remain unchanged; no
retained-data conversion or reset is required. All three Persistence packages
retain their coordinated release identity; package versions are left to release
preparation.

### Archive qualification

The extracted-package consumer reads its direct arithmetic requirement from the
normalized Metrics Stable archive manifest. This removes the separate 0.15
selection that caused graph admission to reject the 0.16 adoption before consumer
compilation. Exact selected-lock admission, extracted-package identity checks,
compiler dispatch and final archive/source integrity checks remain required.

### Contributor tooling

The five native development dependencies and the release-metadata/Testkit server
CLI selections adopt published IC Tooling 0.68.1 at
`c9c5ef7c44e3d0c3b23c8531a5d43c1800656c0a`. Their published Rust sources are
unchanged from 0.68.0. Tooling raises its Platform/Wire requirements; this
consumer already selects Platform 0.6.15 and leaves optional Wire support off.
The prior Tooling adoption changes its five package versions/checksums; the
Metrics adoption changes only the arithmetic package version/checksum. The
independent runtime graph remains unchanged.

Prepare the selected CLIs explicitly with `make install-release-tools
install-runtime-server`; existing admitted 0.68.1 installations can be reused.
PocketIC client/server 16.1.0, the qualified stable-structures 0.7.2 substrate,
compiler pins and the reviewed Shared snapshot remain selected. This tooling
change itself requires no library or retained-data migration.
