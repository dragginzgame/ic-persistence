# IC Persistence 0.53

## [0.53.1] - Unreleased

### 🩹 Fixed

Backing teardown retires its process-local identity claim before destroying the
backing allocation. Construction establishes backing ownership before claiming
it, retaining that ownership until local claim cleanup on refusal or unwinding.
Fallible manager-authority capture finishes before custody transfers into the
shared state. The final runtime or detached handle releases the shared claim
before its backing field drops. A recycled native address therefore cannot
inherit a claim from a backing whose final allocation has already been freed.

This addresses the teardown defect investigated for
[#137 — Fail closed when multiple memory runtimes alias one stable backing](https://github.com/dragginzgame/ic-persistence/issues/137).
Duplicate live owners still refuse before backing IO; handles retain custody
after their runtime drops. The 0.53.0 checkpoint-validation contract, valid IO
path, public signatures, stored bytes, dependencies and toolchains are unchanged.

### 🧪 Testing

Deterministic final-reference tests observe the registry across destruction of
the physical identity allocation, covering final runtime/handle release, typed
growth refusal and panics in manager initialization and authority capture.
Those cases expose stale claims in the previous implementation without relying
on allocator timing. A concurrent independent-backing case complements the
ordering proof; no consumer tests are serialized to mask the failure.

## [0.53.0] - 2026-10-28

### ⚠️ Breaking

Memory now trusts exclusive backing custody between full validation boundaries,
as selected by the maintainer after investigating
[#137 — Fail closed when multiple memory runtimes alias one stable backing](https://github.com/dragginzgame/ic-persistence/issues/137).
Construction, initial bootstrap, successful lease opening and growth validate the
complete manager image. Growth still verifies its projected changes afterward;
diagnostics retain exact bounded metadata validation. Warm bootstrap-binding
verification remains IO-free.

Size, safe/raw reads and writes check poisoning and virtual bounds without a
manager scan. Duplicate constructors still refuse before backing access, claims
survive detached handles, and detected divergence still permanently poisons
every handle. Same-count extent, bucket-map and unused-entry changes remain
detectable at full checkpoints. Prohibited raw edits during a live lease need
not be detected before the next read or write. This explicitly narrows the
per-access corruption-detection guarantee introduced in 0.52.0; hosts must retain
exclusive custody, truthful backing identities and one Memory crate identity.
Public signatures, numeric bounds and stored formats are unchanged. No alternate
unchecked mode, cache, unsafe implementation or migration is added.

### 🔧 Changed

Adopt Platform 0.7.3 in both dependency catalogs and locks and Tooling 0.69.6 in
native dependencies. Preserve the incoming library lock's already selected
versions; the independent lock changes only Platform. Select and prepare Build
and Testkit 0.69.6 CLIs separately. Tooling supplies the macOS source-mode
compilation fix while preserving inventory JSON and permission masking.

The selected Platform interfaces, effective features, stable-structures 0.7.2,
PocketIC 16.1.0 and Rust support remain unchanged. Shared Tooling is already
current at reviewed 0.27.3; no snapshot refresh or sibling dirty source is used.
The cost investigation below retains its original Platform 0.7.2 / Tooling
0.69.5 input identities and is not relabelled as new-graph installed evidence.

### 🧪 Testing

Native and installed corruption fixtures cover both lease-open and growth
checkpoints, followed by refusal through existing poisoned handles. IO coverage
checks that valid size/read/write operations perform no manager metadata reads.
Installed measurements additionally report actual cycle-balance changes around
each update, separately from the inner IO instruction counter.

### 📊 Audit

Matched Linux/PocketIC 16.1.0 measurements use Rust 1.91 Wasm and the same prepared
Testkit 0.69.5 server. For 1,000 one-byte safe reads, inner instructions fall from
192,300,274 to 393,274 (99.8%); the complete update's charged cycles fall from
199,897,192 to 7,798,325 (96.1%). The cycle total includes update and lease-opening
cost outside the inner instruction counter. Per-check comparator improvements
helped but retained substantial cost; they are not part of the selected change.

An isolated copy of IcyDB source `684fcc8bfabf6c2a713594e5f0d6ae41866a5c33`
plus its captured incoming dependency/loader edits reproduces both grouping
refusals. A matched local Memory override holds the consumer sources, dependency
selection and budgets fixed while changing verification placement. All nine
grouping cases and the 10,001-row collection/upgrade case then pass. Grouping
queries measure about 132–160 million instructions each within the unchanged
4.5-billion allocation. These are local consumer observations, not published
adoption or a claim about every application workload.

Matched Rust 1.99.1 raw library probes grow by 248–255 bytes and stay within
existing limits. The IcyDB compiler-emitted grouping artifact decreases from
11,837,596 to 11,835,988 bytes; its canonical optimized artifact decreases from
6,998,583 to 6,997,813 bytes. Those consumer artifacts use its existing development
profile and optimizer, separately from Memory's raw probe measurements.

Exact source/lock/artifact identities, controls, setup failures and qualification
logs remain at `/tmp/ic-persistence-cost-137/`. A temporary no-verification
attribution control is not a candidate or qualification artifact. No sibling
checkout is modified and no query budget is increased. Package versions stay
0.52.1 until the maintainer's separately authorized release.
