in the library's native dependency catalog, preserving the incoming lockfile's
already selected versions. Align the separately prepared Build release editor
and Testkit server CLI at 0.69.5. Optional Platform capabilities remain disabled;

The optional sccache catalog entry does not activate a compiler cache. Updated
maintenance policy does not activate or reconfigure scheduled runs.

## [0.52.0] - 2026-10-28

### ⚠️ Breaking

Runtime constructors now require `MemoryBacking`, extending the host's Memory
contract with a consistent physical identity across aliases and wrappers.
VectorMemory and default canister stable memory are supported directly. Custom
backings delegate to their underlying identity or retain an Rc/Arc identity
allocation; foreign wrappers need a host-owned newtype. Borrowed/non-Clone
backings remain supported. Hosts must use one Memory crate identity and share
one committed runtime across components.

A process-local backing claim rejects duplicate construction before backing IO
and stays alive until the runtime and every detached handle/collection drop.
Errors and ordinary unwinding release custody; forgotten owners remain occupied.
Native claims coordinate across threads; canister upgrades discard old heap
claims and admit retained stable bytes through ordinary validation.

Size, valid IO, opens and growth compare the complete bounded MGR V1 metadata
image before cached manager translations can be used. Successful growth projects
only its known header/table edits into expected authority. Count, same-count
extent and bucket-map divergence poison the owner and refuse further access;
foreign bytes are never silently adopted or repaired. Invalid IO bounds still
refuse before backing access. Ordinary capacity errors preserve their typed
failure/no-write behavior. Allocation diagnostics reuse the same bounded two
metadata reads. Valid IO and zero-grow now perform bounded metadata verification.
Each check reads 34,848 manager bytes; successful growth checks before and after
its metadata update. This adds stable IO even for small data operations. Exact
word comparison avoids byte-at-a-time Wasm comparison without omitting image bytes.

These safeguards address
[#137 — Fail closed when multiple memory runtimes alias one stable backing](https://github.com/dragginzgame/ic-persistence/issues/137).
Raw aliases and unmanaged managers remain prohibited, including over excluded
IDs: reservations do not divide the manager's bucket allocator. Checks are point
observations, not transactions against arbitrary concurrent raw IO, dishonest
backing identities, other processes or separately linked Memory crate copies.
MGR V1, ledger and collection bytes remain unchanged; no reset/migration is added.

### 🔧 Changed

Select published Platform 0.7.1 in both catalogs and Tooling 0.69.3 compatible
minimums. The library lock advanced externally to Tooling 0.69.4 during this work
and is preserved and qualified. Build/Testkit CLIs remain separately selected at
0.69.3. Metrics 0.16.3 remains current. New
optional Platform provider/gzip features stay disabled. The stable-structures
0.7.2 identity, PocketIC 16.1.0 client/server pair, selected features, compilers
and Rust 1.91 floor are preserved. Externally selected library lock bytes are preserved;
the independent lock updates only the Platform entry/its existing error edge.
Shared Tooling remains the reviewed 0.26.26 snapshot.

### 🧪 Testing

Retained-cell fixtures release their previous governed lease before testing
occupied cells, malformed headers or payload limits. These cases still verify
that refusals preserve the existing cell bytes. Separate coverage verifies that
both live cells and detached handles block duplicate fixture creation and opening
without any backing writes, then permit reopening after the final lease drops.
