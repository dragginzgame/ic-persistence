# IC Persistence 0.50

## [0.50.5]

Use Shared's explicit executable selection in Make, native offline reuse and
compact evidence. The full canonical catalog remains validated, while installed
qualification requires only `wasm-opt`. Previous bundles and failed candidates
remain retained; full evidence collection keeps its existing interface.
Production APIs, formats, pins, compilers and both lockfiles are unchanged.
The committed Shared 0.26.2 snapshot requires exact-source producer and consumer
hosted acceptance before integration
([#127 — Adopt explicit wasm-opt selection after qualified Shared 0.26 delivery](https://github.com/dragginzgame/ic-persistence/issues/127)).

Native jobs explicitly prepare the declared library MSRV for extracted-package
qualification. Offline compiler admission precedes expensive validation and
standalone packaging; missing compilers refuse without builds or installation.
The existing Clippy-first ordering, archive MSRV execution and source/lock/tool
selections are preserved.

## [0.50.4] - 2026-10-21

Build and Host libraries select 0.63.0 with default features disabled. The
separately prepared Build metadata editor and Testkit server CLI select 0.63.0
with `cli`, including offline checks and interrupted-release bootstrap. Prepared
CLI receipts bind that feature selection; older tool receipts cannot admit it.

The runtime harness uses raw PocketIC calls, so removal of Testkit’s Candid and
Metrics APIs requires no local source migration. Platform remains 0.6.0 and
PocketIC client/server remain 16.1.0. Production dependencies and stored formats
are unchanged. Prepare the new binaries explicitly with `make install-tools`
and `make install-runtime-server`.

All 60 release-tool tests, the CLI-selection/bootstrap fixtures, Clippy and the
Rust 1.91 helper check pass. Installed Linux IO/upgrade qualification passes all
four Wasm variants; see [runtime evidence](../runtime-io-qualification.md).

## [0.50.3] - 2026-10-21

The independent runtime harness selects IC Platform 0.6.0 through a compatible
0.6 requirement. Its existing `pocket-ic` feature includes the new `principal`
feature, so no additional feature or source changes are required. PocketIC stays
at 16.1.0; production dependencies, stable formats and toolchains are unchanged.
Compile checks do not replace installed IO/upgrade qualification.

## [0.50.2] - 2026-10-21

Remove the completed initial Storage version conversion and call the canonical
inheritance checker directly. Release fixtures use two coordinated packages;
bootstrap qualification covers lock-first and manifest-first interruption.
Pre-consolidation plans require their original source/tooling and remain retained.

CI publishes the failure-evidence archive produced during validation rather than
running the fixture again. Archive rejection cases package once, verify those
archive digests before reuse, and independently exercise drift and duplicate
identity refusal before compilation. Normal archive qualification is unchanged.

Select IC Build and Host 0.62.1 through compatible root requirements, preserving
the already-updated root lockfile. Align the separately installed metadata editor
and Testkit server CLI on 0.62.1. The independent runtime harness now selects
Platform 0.5.1; its PocketIC client remains 16.1.0, matching Testkit’s unchanged
16.1.0 server selection. Production dependencies, stable formats and Rust
toolchains are unchanged.

Prepare selected tools explicitly with `make install-release-tools` and
`make install-runtime-server`. Earlier installed-runtime receipts retain their
original tool identities; source adoption and compile checks do not establish
new installed IO/upgrade qualification.

## [0.50.1] - 2026-10-20

Validation runs the repo-tool fixtures once through `test-tooling`, with the
normal parallel test runner. The subsequent serial workspace test pass skips
that already-qualified module, retaining product test serialization and all
other workspace tests. Standalone `make test` continues to run the complete
workspace suite. The release-adapter fixture checks this dispatch sequence.

The publication adapter sends an application-identifying User-Agent with its
repository contact URL on every crates.io observation. Ordinary `make publish`
no longer needs a temporary curl configuration to avoid the generic-client 403.
Failed observations identify the crate, version and HTTP status, while retaining
the refusal to treat unknown responses as absence or retry publication.

Publication fixtures check the request identity during initial upload and resume,
and verify that 403 and 503 responses stop before any upload. This is a tooling
fix; package APIs, persisted data and dependency selections are unchanged.

## [0.50.0] - 2026-10-20

Memory and Storage now share one repository, dependency catalog, root lock and
reviewed Shared Tooling 0.25.9 setup. Both original Git histories and unpublished
branch/PR heads are preserved. The package implementations and persisted formats
are unchanged. Metrics and downstream application repositories remain outside
this consolidation.

The next authorized minor release synchronizes ic-memory and ic-storage at
0.50.0. Repository movement alone does not alter public contracts; advancing
Memory across a pre-1.0 minor creates a new Rust dependency identity, so direct
consumers of both packages must align both requirements. There is no umbrella
crate, legacy decoder, allocation renumbering or collection data migration.

Release receipts bind both archives. Publication observes registry checksums and
orders Memory before Storage, permitting explicit resume after partial upload.
Independent archive consumers qualify one Memory identity, lease exclusivity and
reopen behavior on native/MSRV builds, plus the Wasm compilation boundary.
Archive qualification seeds disposable locks from the repository selection,
admits external package versions, sources and checksums, and verifies that both
crate identities resolve only to their extracted archives before locked builds.
It also checks the retained archive, unpacked-file and source-input hashes after
qualification.
The release-ordering fixture includes the archive-admission check in its expected
validation sequence, while retaining the assertion that Clippy failure stops
later stages.

See the [migration map](../migration/ic-persistence.md) for exact input revisions,
retained work, isolated qualification exceptions and separately authorized cutover.
