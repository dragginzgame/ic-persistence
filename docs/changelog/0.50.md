# IC Persistence 0.50

## [0.50.17]

IC Persistence owns the opt-in `ic-metrics-stable` adapter previously maintained
in IC Metrics. Its complete Rust implementation and regression tests are imported
unchanged; the arithmetic crate remains an external dependency on its independent
0.15 line. [The migration guide](../migration/ic-metrics-stable.md) records provenance,
ownership, integration order and unchanged API/storage contracts.

The adapter inherits Persistence's workspace version and uses the same local
Memory/Storage identities. Future users select all three from one published
Persistence release line; the crate name and module paths remain unchanged.
Existing V1 rows and B-tree storage need no conversion or reset.

Release preparation projects every local package version and both internal
requirements together. Interrupted bootstrap copies all three member manifests;
receipts bind all three archives, and registry reconciliation observes every
package before uploading in Memory, Storage, Metrics Stable order. Prior release
receipts remain source-bound and must be recovered with their original tooling.
Independent archive qualification exercises counter persistence and allocation
lease custody on native development/MSRV compilers and checks Wasm compilation.

## [0.50.0] - 2026-10-20

Memory and Storage now share one repository, dependency catalog, root lock and
reviewed Shared Tooling 0.25.9 setup. Both original Git histories and unpublished
branch/PR heads are preserved. The package implementations and persisted formats
are unchanged. Metrics and downstream application repositories remain outside
this consolidation.

The next authorized minor release synchronizes ic-memory and ic-storage at
0.50.0. Repository movement alone does not alter public contracts; advancing
Memory across a pre-1.0 minor creates a new Rust dependency identity, so direct
consumers of both packages must align both requirements. There is no umbrella
crate, legacy decoder, allocation renumbering or collection data migration.

Release receipts bind both archives. Publication observes registry checksums and
orders Memory before Storage, permitting explicit resume after partial upload.
Independent archive consumers qualify one Memory identity, lease exclusivity and
reopen behavior on native/MSRV builds, plus the Wasm compilation boundary.
Archive qualification seeds disposable locks from the repository selection,
admits external package versions, sources and checksums, and verifies that both
crate identities resolve only to their extracted archives before locked builds.
It also checks the retained archive, unpacked-file and source-input hashes after
qualification.
The release-ordering fixture includes the archive-admission check in its expected
validation sequence, while retaining the assertion that Clippy failure stops
later stages.

See the [migration map](../migration/ic-persistence.md) for exact input revisions,
retained work, isolated qualification exceptions and separately authorized cutover.
