# IC Persistence 0.56

## [0.56.1]

### 🧹 Cleanup

Logging save comparison consumes the temporary log produced by bounded decoding
through `Log::into_snapshot()`. The host's borrowed current log still uses an
explicit copied snapshot. Canonical restoration, corruption/continuity admission,
record bytes and identical-save write suppression are unchanged.

The workspace now requires published Logging 0.17.5, whose consuming accessor
was merged in [Observability PR #100](https://github.com/dragginzgame/ic-observability/pull/100).
The selected lockfile uses that registry release; no candidate-source override
or unpublished dependency is required.

The follow-on maintenance batch shares one source-bound preparation/rollback plan
and observes artifact locations once within each qualification phase. Retained
receipts, archive ordering, refusal precedence and root-manifest-last publication
remain intact. Release responsibilities and large regression suites are grouped
by contract; earlier qualification reports remain preserved in the history guide.

The ledger writer and reader now use the same private positional row schema with
borrowed serialization and no extra collected row buffer. Runtime committed state
and doctor recovery outcomes are explicit. Histogram continuity separates bucket
monotonicity from interval arithmetic, and Logging compares contiguous retained
history directly. Golden bytes, public errors/const APIs, custody and corruption
boundaries are unchanged. No performance improvement is inferred from these structural changes. Focused
installed qualification is recorded separately with its actual source inputs.

## [0.56.0] - 2026-10-29

### 💥 Breaking

Memory now stores both its allocation ledger and the enclosing Cell value using
IC Wire. `ICML` framing and the `ICMWIRE1` protected marker distinguish the new
contract. The prior CBOR formats are retired with no old decoder, converter,
fallback or automatic reset. Hosts must arrange fresh/reset memory or a separately
reviewed transition before installation. Never clear only the allocation ledger
while leaving application collection bytes behind.

Wire owns bounded serialization and exact decoding. Memory retains key/slot
admission, allocation custody, byte/count ceilings, checksums, successor rules,
corruption refusal and same-format recovery. Logical keys borrow input until
validated. The local CBOR syntax walker, custom bounded writer and CBOR dependency
are removed. Raw decode errors now expose `ic_wire::Error`; runtime encoding
failures use `StableCellLedgerEncode`. Manager/Cell headers and application
collection formats stay unchanged.

The main workspace dependency graph no longer contains `serde_cbor` or `half`.
The independent PocketIC qualification graph can retain CBOR through its external
client; that independent graph and provider remain unchanged.
No deployed data is reset and no release or publication is executed here.

### 🧹 Cleanup

Bounded Cells delegate fixed/maximum retained-length admission to the substrate's
`Storable::check_bounds` before invoking the application's decoder. The adapter
still refuses unbounded types and preserves current Cell bytes and failure
boundaries. The interrupted-bootstrap fixture derives its member-manifest
checksum roster from the canonical package list. Packaging command construction
has one base builder; only development preparation appends `--allow-dirty`, while
final qualification keeps the clean-source path.

Adoption guidance links authoritative catalogs, locks and executable pins instead
of repeating changing version inventories. The handoff separates released-source
history from the later lockfile follow-up and scoped qualification. Those earlier cleanups preserve their public APIs, dependency selections,
release receipts and stored formats.

Release execution and durable-file effects now live behind one private adapter,
while shared substitute fixtures support scenario modules grouped by preparation,
recovery, publication and admission. Ledger regressions likewise separate codec,
transition and recovery contracts. Existing scenarios and refusal boundaries are
preserved. The package roster is parsed once from its existing JSON authority;
the sorter uses standard slice reversal for its descending-input fast path.
Host guidance now includes all four default workspace packages.
