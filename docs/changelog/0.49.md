# 0.49 release notes

## [0.49.1] - 2026-10-19

The independent runtime qualification runner consumes published IC Platform 0.2
with only its optional native PocketIC interface. Platform supplies upstream
client identities; Testkit retains explicit server preparation and lifecycle.
The runner's lockfile selects PocketIC client 16.1.0, matching the selected
server. The old direct 16.0.0 dependency and its exact-pin exception are removed.

This is a contributor qualification update. The library dependency graph,
allocation APIs, stored bytes, Rust floor and selected Testkit CLI are unchanged.
Installed acceptance belongs to the new client/server pair; earlier client
16.0.0 receipts remain historical evidence. The
[qualification record](../runtime-io-qualification.md#ic-platform-02-client-boundary--2026-10-19)
separates compile evidence from pending installed acceptance.

## [0.49.0] - 2026-10-19

### Align the retained-ledger codec with serde_cbor

The library replaces Ciborium with serde_cbor 0.11.2, the version also selected
by IC transport types and PocketIC in the qualification graph. There is one
maintained CBOR backend. Memory retains its bounded writer, pre-allocation syntax
checks, exact consumption and bounded collection visitors. Current fixtures,
`ICMKEY01`, allocation bindings and checksum inputs remain byte-identical; no
conversion, image retirement, reset or additional stored format is introduced.

This addresses [#124](https://github.com/dragginzgame/ic-memory/issues/124).
The minor release is required by the public error contract:
`StableCellLedgerError::Record` and the fixture-only commit-store decoder now
expose `serde_cbor::Error`. Consumers that name, construct or downcast the old
Ciborium error type must update. Error text remains diagnostic; use typed errors
and categories rather than matching codec prose. Runtime handles, allocation
mappings, ledger bounds, Rust floor and substrate pin are unchanged.

The [codec qualification](../current-ledger-qualification.md#049-cbor-backend-replacement-2026-10-19)
records byte compatibility and installed old-to-new upgrade checks. Standalone
Memory Wasm probes grow by 85–92 KB versus Ciborium. Existing downstream uses of
serde_cbor may share reachable implementation, but actual application size has
not been measured; dependency alignment is not a demonstrated size saving.
