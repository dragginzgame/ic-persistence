# 0.49 release notes

## [0.49.4] - 2026-10-20

Shared Tooling 0.25.8 accepts numbered ` - Unreleased` release-note headings and
replaces that marker with the saved UTC date during preparation. Both root and
detail notes use the same finalizer, preserving history and recovery checks.

Validation runs the existing all-target Clippy gate after tool admission and
before fixture suites, tests, Wasm builds and packaging. Sequential Make recipes
stop later stages on lint failure even with parallel execution. The selected
lint scope and feature-specific fixture gate are unchanged. This is contributor
tooling only; library APIs, dependencies and stored bytes are unchanged.

Native release tooling selects published Build 0.24.0 and Host Artifacts, FS and
Process 0.32.0 with defaults disabled. Build now shares Memory's Host identities,
removing Host 0.31 from this tooling graph. Cargo command rendering, metadata
decoding, bounded capture and retained failure evidence are unchanged. Host's
Platform/Principal change is outside Memory's selected capabilities; the library
graph, Rust floors and stored bytes are unchanged. The separately selected
release editor and runtime qualification graph keep their existing selections.

## [0.49.3] - 2026-10-20

Release bootstrap handles an empty editor-admission argument list under Bash
3.2's nounset behavior. Standard release cache preparation can select explicit
tool setup without failing on array expansion; ordinary recovery retains its
offline check. The release-adapter fixture prints its failing command and bounded
bootstrap diagnostics while preserving the failed attempt.
Validation runs this shell fixture before the Rust test suites. Its installer
assertions follow the selected editor pin instead of maintaining a second version.

`make check-production-graph` checks the default Wasm library's locked normal/build
graph through Shared Tooling. Validation excludes native Host, Build, Testkit and
PocketIC packages, together with test-only JSON/TOML/UI-test dependencies. Root
dependency-role sections match those consumers. This check adds no dependency,
does not change stored bytes and does not replace compilation or size budgets.

Repo-tool and the installed qualification runner use Clap for command parsing,
help and argument errors. Existing commands, successful output and publication
environment policy remain unchanged. The runner rejects trailing arguments
instead of ignoring them. Argument errors use Clap's exit status 2; operation
failures retain their existing handling. Clap is a native development dependency
in the root workspace and belongs only to the independent host runner's separate graph;
production Wasm explicitly excludes the Clap family. Package Rust floors and
runtime behavior are unchanged.

The pending Build 0.23 selection uses its metadata command renderer and canonical
decoder. Host retains bounded process capture and complete-success admission;
metadata stdout/stderr limits and error evidence remain unchanged.

## [0.49.2] - 2026-10-20

- Select Rust 1.99.1 for development and matching CI checks, retaining existing
  package MSRVs.

Repo-tool consumes IC Build 0.22's pure Cargo manifest and lock rendering API.
The Shared Tooling 0.25.4 snapshot retires the two Perl renderers. Memory retains
independent semantic projection checks, saved originals, source/package receipts,
interruption recovery and rollback. Shared continues to own changelog rendering.

Interrupted manifest/lock bootstrap uses the pinned published Build editor with
an explicit input allowance. Common tool setup prepares it; ordinary admission
is offline. Standard release bootstrap can prepare the selected tool, preserving
caller-selected offline settings. Recovery copies source as regular files and
refuses CR/LF in its target directory before creating tooling state. Both
workspace formatter sequences use grouped manifest sorting.

Shared's selected-tool installer supports explicit Cargo features and verifies
them against the installation receipt. Memory's selected tools remain featureless;
the changed build policy requires explicit setup again and retains prior slots.

Failure-evidence collection delegates tool selection and archive orchestration
to Shared. A failed selector's partial output is retained as diagnostics and
cannot admit external payloads. Memory still owns product log selections,
redirected-parent refusal, collection completeness and hosted transport checks.

The native tooling lock selects published Host 0.31.1. Its Build 0.22 dependency
still exposes Host 0.30 process types, so this graph cannot compile repo-tool
until an aligned Build release is adopted. The fix is prepared in
[Build PR #80 — Align exposed Host types with published 0.31](https://github.com/dragginzgame/ic-build/pull/80).
Qualification against that proposed Build source passes the helper tests,
strict Clippy and Rust 1.91 checks in a disposable checkout; no source override
is delivered. Registry adoption and its actual-graph checks remain required.

This contributor-tooling change leaves the library API, stored format, Rust
floor, library dependency graph and independent runtime graph unchanged. Run
`make install-tools` after adoption to prepare the selected tool receipts.

## [0.49.1] - 2026-10-19

The independent runtime qualification runner consumes published IC Platform 0.2
with only its optional native PocketIC interface. Platform supplies upstream
client identities; Testkit retains explicit server preparation and lifecycle.
The runner's lockfile selects PocketIC client 16.1.0, matching the selected
server. The old direct 16.0.0 dependency and its exact-pin exception are removed.

This is a contributor qualification update. The library dependency graph,
allocation APIs, stored bytes, Rust floor and selected Testkit CLI are unchanged.
Installed acceptance belongs to the new client/server pair; earlier client
16.0.0 receipts remain historical evidence. The
[qualification record](../runtime-io-qualification.md#ic-platform-02-client-boundary--2026-10-19)
separates compile evidence from pending installed acceptance.

## [0.49.0] - 2026-10-19

### Align the retained-ledger codec with serde_cbor

The library replaces Ciborium with serde_cbor 0.11.2, the version also selected
by IC transport types and PocketIC in the qualification graph. There is one
maintained CBOR backend. Memory retains its bounded writer, pre-allocation syntax
checks, exact consumption and bounded collection visitors. Current fixtures,
`ICMKEY01`, allocation bindings and checksum inputs remain byte-identical; no
conversion, image retirement, reset or additional stored format is introduced.

This addresses [#124](https://github.com/dragginzgame/ic-memory/issues/124).
The minor release is required by the public error contract:
`StableCellLedgerError::Record` and the fixture-only commit-store decoder now
expose `serde_cbor::Error`. Consumers that name, construct or downcast the old
Ciborium error type must update. Error text remains diagnostic; use typed errors
and categories rather than matching codec prose. Runtime handles, allocation
mappings, ledger bounds, Rust floor and substrate pin are unchanged.

The [codec qualification](../history/ledger-qualification.md#049-cbor-backend-replacement-2026-10-19)
records byte compatibility and installed old-to-new upgrade checks. Standalone
Memory Wasm probes grow by 85–92 KB versus Ciborium. Existing downstream uses of
serde_cbor may share reachable implementation, but actual application size has
not been measured; dependency alignment is not a demonstrated size saving.
