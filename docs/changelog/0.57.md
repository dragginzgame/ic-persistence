# IC Persistence 0.57

## [0.57.0] - Unreleased

### ⚠️ Breaking

Logging Stable adopts the published Logging 0.18 contract. Hosts supply an explicit
combined retained-text limit; the adapter supports at most 65,536 configured text
bytes, distinct from the same-sized encoded-record ceiling. Engine restoration
recomputes text usage and the adapter admits combined text before making owned
entry copies. The current checkpoint uses `ICL` discriminator 3 and carries all
four fixed limits. The maintainer explicitly retired discriminator-2 checkpoints;
old rows refuse load, save and normal removal. Hosts own deliberate row retirement
through the governed map or fresh allocations. No deployed reset, old decoder,
inferred budget or automatic fallback is included. This requires the next
coordinated minor release; package versions are unchanged during preparation.

### ⬆️ Dependencies

Both maintained workspaces select published Platform 0.9.1, preserving the exact
stable-structures 0.7.2 substrate and PocketIC 16.1.0 client/server pair. Production
Wasm uses Platform's embedded IC0/executor rather than external suppliers. Metrics
and Logging select 0.18.1; Metrics keeps its current durable Wire format and
continuity/arithmetic checks. The root's incoming Wire 0.7.25 selection is retained;
the independent host graph keeps Wire 0.7.22. Build/Testkit executable pins and
common host/IC tool catalogs are unchanged.

Platform's singleton guard is now selected only with executor/runtime features,
so storage-only and native PocketIC graphs do not claim an executor owner. The
Logging canister fixture still selects the guard through CDK. Public source APIs,
Logging discriminator-3 bytes and Metrics durable bytes remain unchanged by these
patch updates; both Observability packages retain their existing layout.

Shared Tooling 0.27.11 is exported from its reviewed committed source. Graph
observation and retained input checkpointing keep failure evidence and drift
refusal. The generic publication adapter remains opt-in; Persistence retains
its coordinated receipt/publication owner. Fixture support uses ordinary module
discovery without changing schemas or binary-owned runtime custody. Scoped source
lint expectations replace allowances; existing configuration-level style choices
retain documented reasons.

### 🧹 Cleanup

Logging save compares and encodes borrowed complete checkpoints, avoiding current
history copies while preserving immutable retained rows, watermark regression
checks and identical-save write suppression. No throughput improvement is inferred.

Runtime construction and bootstrap have separate private implementation owners.
The same constructor, recovery, policy, publication and binding checks run in
the same order; lifecycle state, public methods and allocation custody are
unchanged. Stable-cell contract tests live beside the implementation in a child
module and continue to use the same retained Wire fixtures.

Recovery tests reuse path-bound byte snapshots for receipts and retained archives,
including interrupted-publication retries. Corruption, permission, file identity,
retention and command-effect assertions remain explicit. The handoff records
batch evidence and links canonical contracts instead of duplicating their
inventories or presenting past checkout state as current.

### 🧪 Testing

Logging qualification covers multi-row text-budget eviction, an individually
oversized append, forged retained usage, explicit old-row administration and
canonical reopen. Installed probes preserve query non-persistence, update/upgrade
rollback and empty/exhausted watermarks while exercising the new text ceiling.
