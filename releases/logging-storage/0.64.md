# Logging Storage 0.64 notes

## [0.64.0] - Unreleased

### ⚠️ Breaking

Codec errors now carry Wire 0.15 identity; align direct Wire dependencies when
exchanging those errors. Checkpoint bytes, budgets and logging semantics remain
unchanged. This source preparation does not publish the adapter.

Storage map construction, mutation and decoding now return typed errors.
The adapter propagates these through `StoreError::Storage`; hosts must handle
fallible construction/iteration. Adapter checkpoint schemas are unchanged.

The repository is now IC Storage. Its adapters are `ic-logging-storage` and
`ic-metrics-storage`; the release groups are `storage`, `logging-storage` and
`metrics-storage`. Update dependencies/imports and release automation using
[the naming adoption guide](../../docs/migration/storage-naming.md). Existing
versions and historical receipts are not relabelled.

Logging Storage now requires Logging 0.24.0. Hosts must align their direct Logging
dependency before supplying `Log` values to `save`, passing `Limits` to `load`
or inspecting restoration errors. The returned `Log` has Logging 0.24 identity;
Logging 0.23 values are not interchangeable with it.

The supplier's release adopts the Rust 1.99.1 floor already required here. Log
semantics, restoration validation, retained-text budgets and engine APIs remain
unchanged. Existing discriminator-3 checkpoint bytes, bounds, eviction, regression
refusal and retention behavior are preserved by the supplier upgrade alone.
The combined Storage adoption below changes the physical backing contract.

Allocation and runtime types now come from `ic-storage`; remove the direct
`ic-memory` dependency and align hosts with the consolidated Storage release.

The combined release adopts Storage's owned allocator and collection formats.
Previous backing images are retired: hosts must use fresh/reset whole backing,
rebuild against Storage-owned `Memory`/`Storable` traits, and update allocation
admission. No legacy map decoder or automatic reset is supplied. Adapter Wire
record schemas and semantic validation remain unchanged; the physical storage
format underneath them is new.
