# Storage 0.68 notes

## [0.68.1] - Unreleased

### 🔧 Tooling

Adopt committed Shared Tooling 0.30.7. Check literal CBOR crate references across
library, helper, benchmark and runtime-fixture sources alongside Candid traits.
The main workspace consumes Shared's central CBOR package inventory; independent
qualification retains its explicit policy and authorized ICSS Git comparison.
Both reject `icrc-cbor`. Frozen-release support is included in the snapshot but
remains disabled until the consumer release hooks are qualified for that mode.

Select published IC Build 0.75.0 for the native repository helper and the
separately installed release-metadata CLI. Storage does not use the removed
shared-target inspection APIs, so no helper API rewrite is required. This is a
native tooling dependency update; production storage behavior and formats are
unchanged. The independent runtime workspace has no IC Build dependency.

### 🩹 Fixed

Vector iterator `last()` uses its final remaining live index instead of scanning
the population. It preserves forward-iteration results after front/back
consumption, shrinking and appending, without changing stored bytes or public
types. Like direct skips, it reads and decodes only the returned record, so it
does not validate discarded records. Published ICSS 0.7.2 retains the full scan.

Map reopening and operation-local region views admit the current framing from
the same header read used to restore the root. Eliminate the separate 12-byte
read without caching stale roots, initializing foreign images, or changing
typed framing rejection. Invalid internals still follow the existing trap policy.

### ⚡ Performance

Vector direct reads use a stack buffer for fixed-width values up to 32 bytes
without destructors. Larger, variable-width and destructor-bearing values keep
owned decoder input; collection layouts and public APIs are unchanged. Against
the immediately preceding Storage implementation, uniform batches of 32 save
6,400 instructions for both u64 and fixed-32-byte reads, including at the full
synthetic handler boundary (about 0.8–0.95%). The 15-type matrix covers all 13
Vector operations; cutoff/reopen and owned-decoder tests cover the new path.
These are workload-specific results, not an application throughput claim.

Resolve each lease's directory index once on admission, using the directory's
append-only entry invariant. Keep extent walking outside the inline cache-hit
path. Regions check their static namespace while the underlying lease admits
the complete live range, eliminating a repeated lookup without weakening bounds.

The copied engines retain ICSS's direct reads into uninitialized buffers through
`Memory::read_unsafe`, following ICSS's destination and initialization contract.
Existing custom backings retain a default through their ordinary read method;
overrides can avoid zeroing bytes that IO overwrites. Collection APIs remain
safe. Fragmented reads, native poisoning and empty-range behavior retain the
governed contract.
The Wasm fast path selects published Platform Runtime >=0.19.4 for its
`stable64_read_uninit` export, with only `ic0` enabled. Both maintained workspaces
adopt that minimum; the qualifier's exact Runtime guard follows its selected version.
[Backing comparison and qualification](../../docs/audits/recurring/storage-icss-backing-parity-2026-11-06.md).

no new production sizing option is introduced. Cell retains one value in each

The `vector-reads` preset separates Get/Set/Push/Pop history from the full
iterator/scan mix, across scalar, fixed-byte, raw chunk and Wire records. Three
rounds preserve updates and restore population after each push/pop pair. Both
libraries' values and final state are checked. Reads immediately after each
mutation and round summaries expose costs
hidden by a single median. This is a collection workload, not a complete Auth
endpoint or a measurement of allocator/page-charge attribution.

A separate frozen-Wasm diagnostic records stable-read addresses/costs in globals
and measures malloc/free inside the original timer. It preserves existing
linear-memory layout and verifies the uninstrumented round trip first. Its

moving into preparation before the timer. Boundary-only measurements show that
the full handler remains essentially unchanged. Separate aggregate and round
execution matrices prevent interpreting this shift as an execution speedup.
No production allocation policy changes follow from that measurement effect.

## [0.68.0] - 2026-11-06

### ⚠️ Breaking

Replace all collection engines with private copied ICSS 0.7.2 source: B-tree,
Set over that B-tree, fixed-stride Vector, cached Cell and governed map regions.
Keep Storage's allocation directory, custody checks, existing application codecs
and successful-call API shapes. There is no production ICSS dependency or ICSS
MemoryManager. [Provenance and adaptations](../../docs/storage/upstreams.md).

Every prior Storage collection image requires an explicit host rebuild/reset or
fresh admitted allocation. Current framing is BTR2 (explicit page size), SVC1 and
SCL1. Hosts must update collection/region framing admission. No legacy reader,
implicit conversion or automatic reset exists. Directory encoding is unchanged.

Inside collections, malformed codecs, engine state and allocation failures now
trap, including operations whose successful-call API still returns Result.
Explicit framing admission and page reservation retain typed failures. Native
mutation panics may leave partial bytes and poison the shared owner; discard its
runtime and leases. IC execution rollback remains the Wasm atomicity mechanism.
There are no collection checksums; application validation cannot detect every
valid-looking byte change. Cell retains its caller-selected load ceiling.

### 🔧 Changed

Delete the prior independent tree/block allocator, record envelopes, node cache,
Vector scan windows, cached length and mutation epochs. Preserve one algorithm
implementation behind the public governed adapter layer. `set_node_cache_budget`
remains a ceiling hint satisfied by the baseline's zero cached bytes, not a cache
enabler. New benchmark runs reject positive Storage cache budgets.

Storage primitive codecs are unchanged. In particular, unsigned encodings differ
from ICSS's default codecs; exchanging images requires matching application
codecs and bounds. Six same-image tests explicitly match those codecs and
exchange updates with separately published ICSS across all supported forms.

The earlier checksum-free ICVEC002 experiment and its measurements remain
historical controls. They do not measure this baseline or establish its speed.
