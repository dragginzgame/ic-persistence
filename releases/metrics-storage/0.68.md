# Metrics Storage 0.68 notes

## [0.68.0] - 2026-11-04

### ⚠️ Breaking

Public measurement values and `StoreError::InvalidState` now use Metrics 0.29
identities. Hosts passing those values must select `ic-metrics = "0.29"`.
Restoration and histogram configuration admission use Metrics' explicit
`persistence` boundary. Recorder types are instrumentation, not Serde report DTOs;
applications own reporting projections.

The adapter retains its own Wire state records, `ICMW` tags, field order,
continuity policy and rejection priority. Existing rows reopen without rewriting
bytes or resetting backing; this source migration adds no retained-format decoder.
See [Observability #130](https://github.com/dragginzgame/ic-observability/issues/130).

Only Metrics Storage requires this public-type alignment. Core Storage and Logging
Storage keep their current dependency requirements. The independent runtime
qualification graph has no Metrics consumer and needs no lockfile update.
