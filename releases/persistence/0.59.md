# IC Persistence 0.59

## [0.59.0] - 2026-10-31

### ⚠️ Breaking

The core catalog and independent qualification workspace select Wire 0.12.1.
Memory's typed codec/bootstrap errors now carry that Wire identity; consumers
constructing or matching them must align to 0.12. This requires a coordinated
core minor release; package versions remain unchanged during preparation.
Retained encoding, durable ledger bytes, bounds and custody are unchanged.
Wire endpoints and Platform schemas remain disabled. No data migration or reset
is needed. Adapter dependency changes are owned by their [Metrics](../metrics-stable/CHANGELOG.md)
and [Logging](../logging-stable/CHANGELOG.md) ledgers.

### ⬆️ Dependencies

Platform 0.15.1 is selected in both maintained catalogs. Its owned identity
reexports now come from the canonical Platform Types 0.15.0 supplier. Production
has one runtime owner; Tooling's native meter retains a non-runtime Platform 0.13
provider. Stable-structures stays 0.7.2 and PocketIC stays client/server 16.1.0.
Wire core 0.12.1 removes the former optional endpoint feature in favor of the
independent endpoint crate. Persistence uses only core codecs, without endpoints
or platform-types schemas; Wire's optional Types 0.1 schema supplier is not
selected alongside Platform's Types 0.15 owner. Codec bytes, limits and admission
are unchanged; no wrapper, schema compatibility lane or data reset is introduced.
Build/Host libraries and the group-aware editor remain 0.73.0. Testkit Native and
the separately prepared Testkit server CLI now select 0.73.0. Metrics/Logging
0.23.1 adoption is described in their own ledgers; Metrics native metadata now
shares Wire 0.12, preserving the default native-wire selection.

### 🔧 Changed

[Issue #144 — Separate core persistence and stable adapters into independent release groups](https://github.com/dragginzgame/ic-persistence/issues/144)
selects three groups in the same workspace. Memory/Storage share their group version through explicit package literals. Metrics Stable and Logging Stable keep the current numeric 0.58.1 as
literal package versions and own separate ledgers. Earlier coordinated history
through 0.58.1 is retained once in `releases/history.md`, linked by the root index. Dependencies stay centralized.

The reviewed Shared snapshot selects committed `54fc49e12f439dbe18d232f622a6d78e61773353`
(recorded VERSION 0.27.19, including the symmetric layout and delegated delivery rules), including release-group policy and shared metadata
custody. No live sibling rules or upstream publication scripts are adopted.
The native adapter uses the existing runner and Build renderers; group-bound
selection, exact files, qualified archive maps, tags and receipts preserve other
groups' versions and pending notes. Compatible core requirements retain their
minimum; a breaking core release updates shared requirements without advancing
adapter versions. Publication selects only the admitted group. Full-workspace
archive integration and the complete release gate remain unchanged obligations.
See [commands and real dependency coupling](../../RELEASING.md#release-groups).

All three groups now own `releases/<group>/CHANGELOG.md`; the root is an index.
Core version inheritance is converted to the same literal 0.58.1 values, with
no workspace master version. Release/resume/publication require explicit group
selection. Ledger moves preserve earlier release identities, prose and scope;
relative links follow the moved files. Source/index/receipt custody and
interrupted metadata recovery use the new exact plans without a legacy lane.
